Understand the approach

When enabled, local Codex memories can turn useful context from eligible earlier chats into generated files for future work. Current documentation says the feature is off by default. Memories are produced in the background after a chat has been idle long enough; active or short-lived sessions may be skipped, and generation can pause near usage limits. “We discussed it” is therefore not evidence that a durable memory already exists.

The desktop app offers machine-level controls under Settings, Personalization, including Enable Codex memories and a choice about memories from tool-assisted chats. The /memories command controls whether the current chat uses existing memories or can contribute to future memory generation. Those chat choices do not change global settings. CLI and IDE behavior follows the connected Codex host; ChatGPT web memory is a separate system.

Generated state lives under the Codex home memories directory and can be inspected when troubleshooting. Do not make manual edits there your primary control surface. Keep mandatory project rules in AGENTS.md and important deliverables in canonical project files. Memory can help you find earlier evidence, but a recalled path, package version or business fact may be stale. Recheck the actual source before a consequential decision or action.

A safe fallback when memory is unavailable

When memory is unavailable, use a project checkpoint containing the objective, decisions, source paths and unresolved work. Supply it to the next task. This inspectable artifact is a valid fallback; do not change privacy settings merely to make the tutorial appear successful.

When it does not work

The newest chat is not reflected in memories.

Likely cause: Eligible background generation may not have occurred yet.

What to try: Use the explicit checkpoint; do not claim a failed or successful memory pass without evidence.

Recall reports the old failing status after the fix.

Likely cause: The remembered state is older than the current code.

What to try: Run the current check and state that the old status was superseded.

Common mistakes

  • Expecting a new chat to appear in memories immediately, or treating a skipped pass as proof of a broken installation.
  • Assuming deleting a chat, turning off recall and deleting the local memory store are the same action.
Source mapping & differences · different

Codex has a documented optional local memory store and /memories controls, with background generation and host-specific settings; it is not Claude’s auto-memory directory or singular /memory editor command.
