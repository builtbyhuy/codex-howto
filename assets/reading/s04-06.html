Understand the approach

A subagent thread and a Git worktree separate different things. A thread carries its own conversation and assignment; it may still edit the same checkout as the parent. A worktree provides separate working files backed by shared repository history. It does not isolate every external service, database, port or ignored local file. Decide which boundary the task needs before assuming another thread creates isolation.

For an actual app worktree, use your own disposable Git repository with a reviewed baseline commit. In a new chat choose Worktree beneath the composer, select the intended branch or available start state and submit the task. Verify its returned directory before editing. The app normally uses detached HEAD and offers Handoff/Create branch flows. The offline program performs a separate temporary Git flow with command-local identity; it does not initialize the course checkout or change personal configuration.

Implement starter/normalize.cjs and starter/report.cjs in the chosen checkout, preserving their frozen interface. Record the directory alongside run.cjs starter and candidate.test.cjs results. A passing check in another folder does not establish the destination's state. Review the desired changes, integrate them deliberately and repeat the candidate checks in the destination. Before eventual cleanup, preserve useful work and account for non-Git inputs; a worktree label alone is not a recovery plan.

worktree-demo.cjs copies the lab into a new OS-temporary directory, makes a baseline commit with command-local fictional identity, creates a detached worktree and prints its actual paths/SHA. Both repairs are checked in the worker, while the temporary parent remains broken until the two-file patch passes git apply --check and is integrated. The destination then runs its own four candidate checks. Git environment variables are stripped so an inherited GIT_DIR cannot redirect scratch operations. The original starter and your global Git identity remain unchanged. This is real checkout isolation and integration; it starts zero Codex agents.

Practice and acceptance

Code checks must identify the checkout they tested. Agent threads, shared resources and Git worktrees are separate boundaries.

About your environment

Try it step by step

  1. Use a disposable capstone copy and establish a Git baseline only if Git is already available with a usable identity; do not alter global identity for the lesson.
  2. Inspect status and the baseline commit, then choose the start state explicitly.
  3. For optional actual isolation, use the documented app worktree flow or the bounded Git example in the worked section, and verify the new directory before edits.
  4. Run the capstone candidate inside that actual worktree and retain its path with the output.
  5. Review the desired changes and repeat the candidate check in the destination after integration; account for non-Git files and shared services separately.

Reference answer & rubric Try the exercise before opening

A worktree provides separate working files backed by the same repository history. It is created and verified explicitly; a delegated thread does not imply one.

  1. Inspect the original working tree and preserve unrelated changes.
  2. Choose a baseline commit; create a distinct checkout through the actual supported flow.
  3. Confirm the real path and run the candidate there, not in a terminal still pointing at the original folder.
  4. Integrate the reviewed change and check the destination's files; preserve ignored/local resources before any eventual cleanup.

Answer 3: Review and integrate the intended changes, then check the destination state.

A worktree result is evidence about that checkout. Integration can change the final state and needs its own verification.

When it does not work

The worker edits the original folder despite a worktree plan.

Likely cause: The actual working directory was never confirmed.

What to try: Report and verify the real path before editing; run checks from that checkout.

The isolated check passes but the destination fails.

Likely cause: The integrated state differs or local/ignored inputs were not carried over.

What to try: Inspect the destination diff and prerequisites, then rerun its own relevant checks.

Common mistakes

  • Adding Claude's isolation: worktree field to a Codex TOML role and assuming it isolated edits.
  • Assuming a worktree copies every ignored file or isolates live services and credentials.
