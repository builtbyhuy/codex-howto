Understand the approach

A useful experiment has a question, a baseline and a decision criterion. “Try another approach” is incomplete unless you know what to compare. In Orbit Notes, compare two implementations of searchNotes in notes.cjs against the same uppercase, whitespace, substring and object-preservation checks. One approach can filter the original objects; another can copy and lowercase every returned note. Both may appear to solve search, yet only one preserves the stated identity contract. The method should produce evidence that helps choose, not merely two different summaries.

A Codex chat fork preserves a conversation branch. A Git branch or worktree separates repository work in a different way. Current CLI documentation supports managed worktrees for suitable new or forked local tasks, but a chat fork in the same checkout can still affect the same files. Before parallel implementation, identify which checkout each task edits. Read-only exploration can share a project more easily than simultaneous edits.

Keep the experiment small enough to inspect and reverse. Save a baseline, give both candidates the same input and run the same relevant checks. Do not merge both solutions merely because both produced plausible summaries. Decide using behavior, simplicity and maintenance implications. A passing test is useful evidence, but the final result still needs a human-readable diff and an explanation of what the test does not cover.

A comparison whose losing candidate is plausible

Both supplied implementations normalize the query and match n1/n3. Candidate A filters the original objects; candidate B maps them to new objects with lowercased titles. Running the unchanged checks in two fresh directories gives A six passes, B five passes and one identity failure. Inspect the actual query text too: B alters the displayed titles.

This distinguishes search matching from the preservation contract. A chat fork branches conversation; the two actual temporary directory paths establish file isolation here. Keep the losing result as evidence, then choose the simpler contract-preserving implementation.

Prefer sequential experiments when isolation is unclear

Parallel work is an option, not a prerequisite. If the client cannot establish separate checkouts or the task is tiny, test candidate A, preserve its diff, restore the verified baseline and test candidate B. Record the sequence and keep the evidence. This often gives a beginner a clearer comparison than coordinating several active agents with uncertain file ownership.

From input to result

Compare implementations against the same contract

These candidate mechanisms are compared with the supplied identity/order checks; use separate copies or sequential baselines.

Worked input javascript
function candidateA(notes, query) {
  const needle = query.trim().toLowerCase();
  return notes.filter(note => note.title.toLowerCase().includes(needle));
}
function candidateB(notes, query) {
  const needle = query.trim().toLowerCase();
  return notes.map(note => ({ ...note, title: note.title.toLowerCase() }))
    .filter(note => note.title.includes(needle));
}
Expected result · compare with your run
Both candidates match the same two note IDs for "  REVIEW  ".
Candidate A returns the original note objects in order.
Candidate B creates new objects and changes their title text, violating the preservation contract.

These are complete comparison functions, not two unexplained fragments. Search IDs alone cannot choose correctly: the supplied identity check rejects the cloned objects. Evaluate the implementation copied into notes.cjs against the same six unchanged checks.

When it does not work

Each candidate passes a different set of tests.

Likely cause: The comparison changed its criteria mid-experiment.

What to try: Use the unchanged supplied checks for both.

Two forks overwrite each other.

Likely cause: Separate chats edited the same directory.

What to try: Use separate copies/worktrees or run the experiment sequentially.

Common mistakes

  • Forking two chats into the same checkout and assuming their concurrent edits are isolated.
  • Changing the evaluation cases for the preferred candidate and calling the comparison fair.
