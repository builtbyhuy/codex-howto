Understand the approach

A small agent team is useful when each member owns an independent deliverable and the parent retains integration. Codex's documented subagent workflow should not be presented as a one-to-one copy of Claude's experimental team controls. The capstone needs only two implementation packages and a parent integrator. More titles would add coordination without creating a new independent output.

The ledger assigns A to starter/normalize.cjs and B to starter/report.cjs after a shared interface is established. A handles padded case and invalid status values. B receives normalized records and computes completed-only counts and effort. The parent waits for both code outputs, reconciles their handoffs and checks the combined state. A and B may proceed independently against CONTRACT.md; final acceptance depends on both.

Deliver a candidate that produces total=4, done=2 and doneMinutes=55, passes the four learner grading tests and preserves source inputs. Distinguish the runner's five named integration predicates from the seven frozen-baseline/reference tests. The deterministic simulation supplies reference handoffs with actualAgentsSpawned:false; any real worker activity needs its own observation. A ledger marked complete is useful only when its files and actual checks support that status.

Use the exact two-owner prompt and inspection flow in native-agent-guide.md for actual Codex coordination. The offline route already supplies working solution/normalize.cjs and solution/report.cjs, while candidate.test.cjs grades the editable starter. The real-worktree program proves an A-only handoff is rejected and the destination must be checked after integration. Codex’s documented parent/subagent orchestration reaches this outcome without claiming Claude’s experimental mailbox, automatic task-dependency service or teammate-pane controls. Judge working files and actual worker evidence rather than a fictional team-mode switch.

Reference answer & rubric Try the exercise before opening

The reference combines normalized, validated statuses with a completed-only aggregate and uses parent-owned checks to prevent partial delivery.

  1. Keep A and B's ownership disjoint and freeze CONTRACT.md.
  2. Require changed-file evidence and observed cases in each handoff.
  3. Verify total=4, done=2, doneMinutes=55 and rejection of malformed/duplicate records.
  4. Close the ledger only after combined verification; retain separate not-run status for actual role loading or background observation.

When it does not work

The ledger says complete while the code still contains a starter bug.

Likely cause: Administrative status was treated as acceptance.

What to try: Run the actual combined candidate and reconcile the ledger with its failures.

Many specialists add coordination but no independent outputs.

Likely cause: Work was divided by titles rather than dependency and file ownership.

What to try: Collapse the plan to A, B and the parent integrator; add roles only for a concrete independent need.

Common mistakes

  • Claiming Claude team flags, mailbox paths or split-pane controls are current Codex commands.
  • Treating several agreeing agent summaries as a substitute for checking the product.
