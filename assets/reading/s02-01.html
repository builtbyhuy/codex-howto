Understand the approach

A chat transcript, project instructions and generated memory solve different problems. The transcript records what happened in one conversation. AGENTS.md states durable working guidance in a file the team can review. Local Codex memories can recall useful context from earlier eligible chats when that feature is enabled. None of these is a complete, continuously updated database of the project’s current truth.

Use AGENTS.md for requirements that must apply, such as the correct test command, boundaries around generated files, or how to preserve another developer’s changes. Keep changing facts in their canonical project documents, not duplicated across every prompt. A remembered test command can become stale after a package migration; the current configuration and relevant project instructions are the evidence to inspect before running it.

Local Codex memory is distinct from ChatGPT web memory and is off by default in current documentation. The desktop setting is Enable Codex memories under Personalization; the CLI exposes chat-level /memories controls when available. The IDE uses its connected host’s memory store. Enabling a feature on one computer does not establish the same state on another host, and generated recall does not replace a saved project artifact.

Context classification has a falsifiable result

The rule to preserve WORK-NOTE.md belongs in AGENTS.md. The current count comes from notes.json. The old 4-pass/2-fail result describes the baseline and can become stale immediately after a fix. A request to return only an outline belongs to the current task unless deliberately saved as continuing guidance.

The linked ledger supplies all four cases and a stale-result counterexample. A fresh conversation should be given the task goal and relevant checkpoint; it should not promote every past decision into a permanent rule. Optional memory can locate evidence, but the exercise works without it.

A useful source-of-truth habit

Give each important fact one maintainable home. Reference that file when a task needs it instead of copying its contents into several instruction layers. When two sources disagree, identify their scope and dates before choosing which applies. For example, a recent package script can invalidate an old setup note, but it does not silently authorize a deployment that the current task never requested.

Mandatory guidance needs an explicit, reviewable source. Memory is an optional recall layer, not the only home for a rule.

When it does not work

A prior note count conflicts with the file.

Likely cause: Recall or a duplicated note is stale.

What to try: Use the current canonical file and record which earlier claim was superseded.

The next chat forgets a required rule.

Likely cause: The rule existed only in a conversation or optional memory.

What to try: Put the reviewed requirement in project guidance and verify discovery in a fresh session.

Common mistakes

  • Putting passwords, customer records or one-time instructions into a reusable project-guidance file.
  • Assuming a generated memory is current, complete, or available in every client and on every machine.
