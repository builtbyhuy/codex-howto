Understand the approach

Codex's documented built-in roles are default, worker and explorer. Choose by the task's immediate purpose rather than importing Claude role names. An explorer can trace current behavior and cite the responsible code; a worker can implement an agreed change; the parent or default agent can coordinate and reconcile results. Inspect custom definitions before relying on a built-in name, because a custom role with the same name takes precedence.

In the capstone, exploration should locate both independent defects: missing trim in starter/normalize.cjs and the all-task reduction in starter/report.cjs. It should connect those expressions with the actual baseline result and frozen interface. Implementation then has concrete scope. Package A handles string normalization and its errors; package B validates normalized records and computes completed-only effort. Neither needs an extra specialist merely to rename a role.

After implementation, verification examines the actual combined files. run.cjs starter must return total=4, done=2 and doneMinutes=55. candidate.test.cjs must pass its four learner tests, including cases independent of the main fixture. The separate seven-test reference suite preserves the frozen baseline and checks the supplied solution. Report these different checks clearly. A role label, worker completion message or green reference suite does not establish that the edited starter is correct.

Make role choice a testable assignment. An explorer explains why padded DONE misses the done comparison and why the all-task reduction produces 80, citing the actual starter lines. Workers implement the two frozen contracts. The parent/default agent checks both diffs and runs the combined candidate plus independent invalid-input cases. The guide gives current app, CLI and IDE thread controls, so you can inspect actual delegation rather than merely repeat a role label. If a custom explorer shadows the built-in, preserve its source with the result instead of attributing its behavior to the default role.

When it does not work

A role name looks familiar but is unavailable.

Likely cause: A Claude role name or an unverified custom role was assumed.

What to try: Use current Codex built-ins or inspect an actual installed custom definition.

Exploration expands into implementation before the contract is settled.

Likely cause: The stage's expected output was not bounded.

What to try: Request source evidence first, then issue a separate owned-file implementation contract.

Common mistakes

  • Requesting a Claude-specific built-in name and silently assuming identical Codex behavior.
  • Treating the explorer label as a separately enforced read-only environment.
