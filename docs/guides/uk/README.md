# Почніть роботу з Codex із завдання, яке можна перевірити

**Межі перекладу:** цей вступний посібник доступний п’ятьма мовами. Усі 60 докладних уроків, файли виконуваних вправ, перегляд вихідного коду й перевірки знань залишаються англійською. Вибір мови посібника не перекладає весь курс.

Посібник оновлено **22 жовтня 2026 року**. Документацію продукту перевірено **21 жовтня 2026 року**. Доступність функцій може залежати від версії клієнта, операційної системи, облікового запису та політики організації.

## 1. Відкрийте проєкт, який можете оглянути самостійно

Codex — агент для програмування: він читає файли проєкту, пропонує зміни та користується доступними інструментами. Почніть із настільного застосунку, де проєкти, чати й попередній перегляд розташовані в одному робочому просторі. Для встановлення та входу скористайтеся [офіційною інструкцією](https://learn.chatgpt.com/docs/app). Якщо застосунок уже встановлено, спершу перевірте наявну версію. Виберіть Codex і відкрийте окрему навчальну теку. Успішний вхід ще не доводить, що відкрито потрібний проєкт.

Відкрийте [перший урок](https://codex-howto.hokhachuy1234.chatgpt.site/#lesson/s01-01) і завантажте [Orbit Notes](https://codex-howto.hokhachuy1234.chatgpt.site/labs/project-workflow.zip). Розпакуйте архів: він зберігає структуру `labs/project-workflow/` усередині кореневої теки розпакування. У теці цієї вправи виконайте:

```text
node create-workspace.cjs
```

Потрібен уже встановлений Node.js 20+. Команда поверне шлях до нової тимчасової теки; відкрийте в Codex саме її. Якщо Node немає, можна скопіювати `starter/` через файловий менеджер, але зафіксуйте, що перевірки коду ще не запускали. Не додавайте особисті документи до навчальної вправи.

## 2. Спочатку перевірте факти, потім дозволяйте редагування

Після відкриття отриманої теки надішліть:

```text
Лише читання: підтвердь фактичну робочу теку. Прочитай README.md, AGENTS.md і notes.json. Опиши призначення проєкту, чотири ID нотаток і чи вказано адресу розгорнутого сайту. Перевір наявність package.json, перш ніж приймати інструкцію тестування з README. Нічого не редагуй і не встановлюй.
```

Самостійно звірте відповідь із файлами. ID чотирьох вигаданих нотаток: `n1`, `n2`, `n3`, `n4`. Адресу розгортання не задокументовано. Початковий README радить `npm test`, але `package.json` відсутній: це навмисна суперечність для вправи. Обґрунтована відповідь має виявити її, а не вигадати URL чи встановити залежності, щоб приховати проблему.

`AGENTS.md` містить проєктні інструкції. Проте сама наявність файла не доводить, що кожен клієнт знайшов його та виконав усі вказівки. Якщо названа робоча тека не збігається з відкритою, спершу виправте контекст. Не переходьте до редагування стороннього проєкту лише через впевнений тон відповіді.

## 3. Виправте одну помилку й перевірте результат

У власній тимчасовій копії зафіксуйте початковий стан:

```text
node --test checks.cjs
node cli.cjs REVIEW
```

Очікувано **4 перевірки проходять, 2 завершуються помилкою**. Пошук має знаходити підрядки незалежно від регістру й ігнорувати пробіли навколо запиту. Доручіть Codex виправити `notes.cjs`, зберегти початкові об’єкти нотаток та їхній порядок і замінити інструкцію в README.md на справжню команду перевірки. Не змінюйте `notes.json`, `checks.cjs` і `WORK-NOTE.md`. Потім повторіть:

```text
node --test checks.cjs
node cli.cjs "  REVIEW  "
```

Мета — **6 успішних перевірок** і рядки `n1: Review launch checklist` та `n3: Review documentation`. Відкрийте змінені файли власноруч. Повідомлення «готово» не замінює результату тестування. Якщо помилки залишилися, передайте точний вивід і попросіть виправити найменшу відповідну ділянку. Не видаляйте невдалі перевірки й не підміняйте весь проєкт готовою відповіддю. Повний розв’язок і критерії оцінювання в пакеті варто переглянути після власної спроби.

Далі потренуйте вузьке відновлення: додайте до README корисний абзац, окремо змініть заголовок невдалим способом і скасуйте лише зміну заголовка. Новий абзац має залишитися. Інший чат не відновлює файли. Якщо Git уже встановлено, додаткова вправа показує базовий стан індексу та справжню різницю файлів. Окрема демонстрація комітів пояснює стійку історію змін. Стан індексу й коміт — різні контрольні точки.

Skill — пакет інструкцій для повторного використання; MCP — протокол підключення інструментів і даних; підагент виконує делеговане завдання; hook обробляє підтримувану подію; plugin об’єднує пов’язані можливості для розповсюдження. Наступні уроки пояснюють їх налаштування й умови доступності.

## 5. Розумійте, що доводять сім практичних пакетів

У [бібліотеці вправ](https://codex-howto.hokhachuy1234.chatgpt.site/#labs) є сім окремих завантажень. `project-workflow` охоплює перший проєкт і відновлення; `cli-pipeline` перевіряє події дочірнього процесу та витягнуті звіти; `skill-workflow` містить повторно використовувану навичку перевірки й детермінований допоміжний засіб; `mcp-workbench` справді обмінюється локальними повідомленнями JSON-RPC; `delegation-capstone` об’єднує два окремі робочі завдання. `hook-policy` відтворює обмежені події та перевіряє докази, пов’язані з файлами; `workflow-plugin` поєднує навичку, інструменти та матеріали для налаштування підключень.

Локальні програми виконуються насправді, але вигадані дані, синтетичні події та імітація делегування позначені. Успішні тести допоміжного засобу не доводять, що Codex викликав skill, обрав інструмент MCP, запустив підагентів чи активував hook. Додаткові інструкції для справжнього клієнта пояснюють, як спостерігати це окремо. Читайте README кожного пакета, працюйте у свіжих копіях і відрізняйте навмисно невдалий початковий варіант вправи від перевірок еталонного розв’язку.

## 6. Не плутайте застосунок, CLI й IDE

**Застосунок** має проєкти, чати та панелі перегляду змін. **CLI** — окремий клієнт у терміналі, де важливі поточна тека й параметри команди. **Розширення IDE** працює у редакторі коду: перевірте корінь робочого простору та користуйтеся його елементами керування. Команда CLI, вставлена в чат застосунку, не стає автоматично командою керування застосунком.

Перевіряйте фактичні меню й підтримувані можливості встановленої версії та дотримуйтеся відповідної гілки уроку. Не вставляйте ключі API чи конфіденційні матеріали в навчальні запити. Дивіться [документацію CLI](https://learn.chatgpt.com/docs/codex/cli), [автентифікацію](https://learn.chatgpt.com/docs/auth) і [дозволи виконання](https://learn.chatgpt.com/docs/agent-approvals-security). Відсутній доступ слід назвати відсутнім доступом, а не заповнювати здогадками.

## 7. Збережіть прогрес або запустіть сайт локально

Навчальний обліковий запис не потрібен. Відкриття уроку записує прогрес; позначайте його завершеним після перевірки роботи. Прогрес і відповіді зберігаються у браузері для конкретного джерела сайту. Тому локальний перегляд і публічний сайт мають різні записи. Перед зміною пристрою або очищенням даних експортуйте резервну копію прогресу в Source library й імпортуйте її в новому браузері. Приватний режим чи блокування сховища можуть завадити збереженню. Сайт сам не запускає приклади для термінала.

Якщо Git і Node.js 20+ уже встановлено:

```text
git clone https://github.com/builtbyhuy/codex-howto.git
cd codex-howto
node scripts/server.cjs
```

Відкрийте `http://127.0.0.1:4173/` і залиште термінал працювати. Для зупинки натисніть Ctrl+C. Встановлювати пакети чи збирати фреймворк не потрібно. Користуйтеся сервером, а не подвійним натисканням на index.html. Для інтерактивного читача потрібен JavaScript.
