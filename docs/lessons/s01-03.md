## Environment

App / CLI / IDE

## Understand the concept

Repeated requests often begin as saved text: a release-note checklist, a repository orientation prompt, or a review routine. Codex previously supported custom Markdown prompts in the user prompts directory, invoked through a prompts namespace. The current official documentation marks custom prompts as deprecated and recommends skills. Existing prompts are useful migration inputs; their presence does not make them the preferred format for new work.

A skill gives a workflow a name, a description of when it applies, and instructions in SKILL.md. Repository skills live under .agents/skills so a team can version them with the project. Personal skills can live in the user .agents/skills directory. Unlike a saved prompt that must be inserted manually, a skill can support explicit invocation and description-based selection. An accurate trigger matters as much as the instructions.

Migration is a behavioral redesign, not a filename substitution. Remove assumptions about Claude paths, slash namespaces or implicit permissions. Identify the input, permitted actions and concrete output. A skill that drafts release notes should not also create a commit, open a pull request or publish a release unless those actions are part of the current authorization. Review and run the workflow in a scratch project before treating it as reusable.


## Explore the details

### A migration changes the workflow contract

The legacy input says review, then asks for npm test, a rewrite and a commit. The starter has no package.json, and a read-only audit should produce findings. The replacement names source files, defines a four-column output and leaves edits for a separately scoped task.

Do not carry Claude-specific argument substitutions, tool front matter or dynamic shell blocks across by analogy. For this instruction-only skill, the target README is ordinary request text. The optional Codex metadata file is a separate documented format; it is unnecessary for this first migration.


### A small migration is easier to trust

Start with a read-only workflow that returns a document. Add scripts only when deterministic processing is useful. Record which legacy behavior remains and what changes, so reviewers can compare the migration without modifying global configuration.



## Example

### Migrated .agents/skills/readme-check/SKILL.md

```markdown
---
name: readme-check
description: Audit README setup claims against source files. Use for read-only README checks, not implementation.
---
Read README.md, notes.cjs and checks.cjs. Check whether package.json exists.
Return Claim, Evidence, Finding and Suggested correction.
Label unrun commands; do not edit, install, commit or publish.
```

## Worked reference

### A concrete command-to-skill migration

The complete local reference skill is supplied under the capstone solution. Review it before copying it into a disposable project.

```markdown
---
name: readme-check
description: Review README setup and verification claims against files. Do not use for code changes.
---
Read the named README and actual project files.
Return Claim, Evidence, Finding and Suggested correction.
Do not edit or install anything.
```

```text
Positive case: README readiness review → relevant workflow.
Excluded case: change the search implementation → separate implementation task.
```

The migration retains the review method while replacing old prompt directories and implicit authority. The answer key identifies unsupported npm test without installing dependencies.

## Common mistakes

- Mechanically renaming .claude/commands to a Codex directory while retaining incompatible front matter and invocation syntax.

- Packaging broad execution authority into a convenience shortcut for what was originally a drafting task.


## Troubleshooting

The skill drafts a fix instead of a review.

The trigger or procedure mixes analysis and implementation.

Narrow its description and body to the findings table, then retest both request types.

The old /prompts entry still appears.

The deprecated local prompt remains installed in that environment.

Do not create another legacy entry; inspect and migrate it through a deliberate maintenance task.
