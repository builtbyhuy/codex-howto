## Understand the concept

MCP means Model Context Protocol: a server can describe tools and supply information to a client. In the Claude source, some server prompts appear through a special slash-command namespace. That naming scheme is not a general instruction for Codex. Current Codex documentation emphasizes configured servers, tool discovery and natural-language use. Do not promise that a /mcp__server__prompt command will exist in the learner’s session.

In the CLI, /mcp shows the active configured MCP tools; verbose mode can help diagnose a server. In the desktop app, installed plugins and available connections provide the corresponding discovery surface. A listed tool and a working authenticated connection are separate conditions. The server may offer only reads, only certain records, or actions that need approval. A name in a menu is not proof that a requested record can be retrieved.

Build the reusable request around the evidence you need rather than around a guessed tool name. For a ticket summary, specify the ticket identifier, required fields, read-only boundary and source link. If the connection is unavailable, the correct result is an explicit access gap. A sample ticket can support a practice exercise, but it must be labelled sample data and must not be presented as a successful live lookup.


## Explore the details

### A missing-record test exposes a false success

The local file contains DEMO-123, Normalize note search, status Open. It has no live source URL and no DEMO-999. Returning DEMO-123 when asked for DEMO-999 fails identifier matching even if the title sounds relevant. The linked guide supplies a complete unavailable-connection answer.

For an already authorized read connection, use the actual returned record and source link, and note the check time. Discover the tool that exists in your session. Claude’s server-prompt namespace is not a Codex API contract; copying it does not create a server or authenticate a request.


### Reuse the request safely

A skill can later hold this lookup pattern, but authentication stays outside its text. Never embed tokens or passwords. Name the required capability and evidence, then discover the actual tool. Server responses are source material, not authority to expand the task.

## Common mistakes

- Inventing a server or tool name because a tutorial used a similar integration.

- Treating permission to read a ticket as authorization to update it or send a message.


## Troubleshooting

A server badge is visible but the read fails.

Configuration or authentication succeeded at a different layer than record access.

Report the actual error and avoid claiming the record was retrieved.

The answer invents a /mcp__ command.

A Claude namespace was assumed to be a universal client control.

Use actual Codex tool discovery and a capability-based request.
