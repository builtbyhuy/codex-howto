## Environment

App / CLI / IDE

## Understand the concept

A slash command is a client control typed into the Codex composer, not a shell command and not an ordinary request. In the interactive CLI, type a slash to open the command menu and filter by name. Treat this menu and the current official command reference as the inventory. A command copied from Claude Code, another IDE or an old tutorial is not valid just because its name sounds plausible.

Start with commands that make the session observable. /status displays session settings and context information; /diff shows the working changes, including untracked files; /mcp lists configured external tools. /plan requests planning before implementation, /review examines the working tree, and /new starts a fresh chat. These controls do different jobs: reviewing a diff does not run tests, and starting a new chat does not restore files.

Desktop and IDE menus have their own command and shortcut sets. In the desktop app, the command menu is available through Ctrl+Shift+P or Ctrl+K on Windows, with corresponding Command shortcuts on macOS. Do not assume every CLI slash command appears in every composer. If a control is unavailable, use the documented interface or ask a plain-language question with a concrete output instead of inventing an alias.


## Explore the details

### Inspect, steer and reset are different controls

Use the app review view to find the exact heading edit; in CLI, /diff is the corresponding working-change inspection. Neither establishes that any test passed. After starting a new chat, README.md still contains the edit. This observable counterexample is more useful than memorizing that /new resets something.

The linked notebook separates desktop actions, CLI composer controls and operating-system shell commands. Try each separately, record unavailable controls, and compare the actual result. An empty MCP list or absent Git history can be a valid observation.


### Read the result, not just the command name

A supported command can still have context-dependent behavior. A review may require a Git repository; a tool list may be empty; account restrictions may hide controls. Record the actual result and client version when troubleshooting. Prefer a narrow diagnosis such as “the CLI menu lacks this item” over a global claim that Codex cannot perform the underlying task.

## Common mistakes

- Typing /status into PowerShell and expecting the Codex composer to handle it.

- Copying Claude-only /rewind or /memory commands and silently assuming Codex has identical behavior.


## Troubleshooting

PowerShell cannot find /diff.

A composer control was entered as a shell command.

Use the Codex composer or desktop Review view.

The expected menu item is absent.

Client version or surface differs from the example.

Inspect current command help and use the documented alternative; record the unavailable control.

## Knowledge check

Which statement about /diff is accurate?

1. It automatically proves the code is correct.
2. It restores every modified file.
3. It helps inspect changes; tests and acceptance remain separate.

<details><summary>Reference answer — attempt first</summary>

3. It helps inspect changes; tests and acceptance remain separate.

A diff shows what changed. It does not prove runtime behavior or undo the working tree.
