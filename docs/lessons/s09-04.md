## Understand the concept

The source's Auto Mode uses a background classifier to review actions. Codex's closest documented mechanism is automatic approval review, exposed as Approve for me when available. A separate reviewer examines eligible approval requests. The main agent still uses its sandbox, network limits, and filesystem scope. This is a change in who reviews a boundary-crossing request, not a grant of unrestricted access.

Review applies to actions that already need approval; routine operations permitted within the sandbox do not all receive a fresh review. The current documentation describes interactive approval policies such as on-request. With approval_policy never, there is no approval prompt to route to the reviewer. Computer Use app-level approvals remain a separate case. Managed requirements and account availability can limit the option.

An explicit review denial is meaningful evidence, not an inconvenience to bypass. The agent should seek a materially safer alternative or explain the required user decision. Repackaging the same outcome through another shell, tool, or indirect command is not a safer path. Automatic review also does not replace the user's task authorization: a request to draft a message still does not become permission to send it.


## Explore the details

### Evaluate a safer alternative by its effect

If an operation would overwrite an external shared file, a safer alternative might prepare a local patch and show the exact proposed change. Merely calling a different program to overwrite the same file has the same effect and is not materially safer. Record the protected resource, intended effect, and reduced exposure in the comparison. This helps both the reviewer and the user assess what changed about the proposal.


### Native control and stopping point

The complete native workflow guide shows the app control and CLI equivalent. It also teaches restoring Ask for approval. The policy fixtures do not invoke automatic review, and no arbitrary destructive test is needed to learn this control.

## Try the workflow

2. Choose Approve for me if available. In supported builds Settings &gt; General &gt; Permissions controls its availability; managed policy can omit it.

3. Use a generated project and a bounded local task. Inspect actual tool and approval activity; ordinary in-boundary work may need no escalation at all.

4. Explain the unchanged workspace-write sandbox and the automatic reviewer for eligible requests. Do not infer a classifier decision from ordinary successful editing.

5. Return the chat to Ask for approval when finished; if a mode is unavailable, retain the supported current mode and record why.

## Reference solution

Map the ordinary action, boundary escalation, reviewer, and task authorization independently.

1. For an allowed workspace read, state that routine access may proceed inside the effective sandbox without an approval request.

2. For a hypothetical out-of-scope write, identify the sandbox boundary first. Automatic review changes who reviews an eligible request, not the writable roots.

3. Inspect the current permission control or /permissions in a supported CLI without changing it. Record availability separately from the mode actually selected.

4. Explain that approval_policy never supplies no interactive approval request to review; do not interpret it as universal user authorization.

5. If review denies the action, propose a materially safer local deliverable or ask about the specific missing authorization. Do not rephrase the same operation to bypass the decision.

## Common mistakes

- Calling Approve for me full access or claiming it reviews every tool call.

- Retrying the same denied effect through an indirect mechanism and labeling it a workaround.


## Troubleshooting

A normal in-workspace read produced no automatic-review item.

Auto-review was expected on every action rather than eligible approval requests.

Check whether the action crossed an effective boundary; absence of review can be normal for allowed work.

Approve for me is missing or disabled.

Client, account, execution environment, configuration, or organization requirements do not expose it.

Record the actual state and follow permission troubleshooting; do not change policy or choose full access as a workaround.

## Scope and differences

different

Codex automatic review swaps the reviewer for eligible approval requests while retaining the sandbox; it is not identical to the source's per-action Auto Mode.


## Knowledge check

Does Approve for me expand writable roots?

1. Yes; it removes all filesystem restrictions.
2. Only when a hook prints allow.
3. No; it changes the review path for eligible requests.

<details><summary>Reference answer — attempt first</summary>

3. No; it changes the review path for eligible requests.

Automatic review does not itself expand the sandbox or enable networking. It evaluates requests at the existing boundary.
