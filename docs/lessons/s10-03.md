## Understand the concept

Flags configure a particular invocation. The most useful beginner controls identify where the task runs and what filesystem access it needs. --cd selects the working directory; --sandbox read-only prevents the agent’s ordinary sandboxed workflow from editing project files. For work that needs changes, the documented workspace-write mode is more appropriate than a broad full-access default. Inspect actual client help because flags and policies evolve.

Approval policy and sandbox scope answer different questions. The sandbox constrains the environment; approval policy determines when the agent requests authorization for eligible actions. A prompt that says “do not edit” communicates intent but does not replace those controls. Conversely, permission to write inside a folder does not authorize publishing a site or sending messages through an external integration. Tool-specific permissions may need separate consideration.

Current configuration precedence gives CLI flags and one-off configuration overrides priority over ordinary defaults, while managed requirements can still constrain allowed behavior. Personal defaults, trusted project configuration and profiles have their own layers. Do not edit global settings to solve a one-run need. The old --full-auto flag is no longer supported in current documentation, so tutorials should use explicit current settings rather than preserve obsolete convenience switches.


## Explore the details

### A wrong-directory counterexample is more than a flag list

The two fixtures deliberately disagree. Compare the planned working directory with the source, then validate the red answer against the blue README to see a factual failure. This exposes correct-looking output carried from an earlier workspace into the current task.

The optional capture uses --sandbox read-only and --ask-for-approval never so a needed escalation fails rather than silently widening the run. The host process writes reports into a fresh temporary directory. These are invocation choices, not persistent Codex setting edits. Review current help and managed constraints before a real run. The global approval flag precedes exec in the supplied runner; an exec-local placement is rejected by the checked client. Its explicit repository-check exception applies only to the known read-only fixture folders.


### A read-only agent is not a read-only shell

If you redirect output with your shell or use a client output-file option, that surrounding process may create a report even when the agent’s project sandbox is read-only. Name the output deliberately and do not overwrite an important source. Evaluate the whole command you are running, including redirection and pipelines, rather than checking only the sandbox flag in the middle.

## Common mistakes

- Using full access to avoid investigating a wrong directory or missing file.

- Assuming a supported flag can override an organization’s enforced security requirements.


## Troubleshooting

An important source file is overwritten by a report.

The surrounding shell redirection targeted the input or another source.

Use a new output path and restore the source from its verified copy.

The wrapper is given a guessed producer status.

Transport evidence was absent at capture time.

Record the actual status with the process wrapper; do not retrofit a successful assumption.
