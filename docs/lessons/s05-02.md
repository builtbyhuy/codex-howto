## Understand the concept

Choose a transport based on where the server runs. Codex documents STDIO for a local process and Streamable HTTP for a server address. STDIO depends on an installed executable, arguments and the environment in which it starts. HTTP depends on a reachable endpoint and any required authentication. Copying an unrelated Claude transport flag or a third-party server command without checking its owner and installation requirements can create a configuration that looks plausible but cannot initialize.

The public Docs MCP uses Streamable HTTP. The example shows its documented CLI registration, but configuration is an intentional change to your selected environment, not something this website performs. Check whether an equivalent entry already exists before adding it. The same Codex host can share MCP configuration across App, CLI and IDE, so changing clients does not necessarily require a second registration. For an OAuth server, sign-in is another step; a visible entry can still be unauthenticated or unable to read the expected record.

Verify the whole path with a small read after setup. Distinguish command not found, connection timeout, authentication failure and a tool-level error. Raising a timeout may help a slow approved server, but it does not repair an incorrect command or missing credential. Keep secret values out of examples and shared files. Prefer documented environment-variable references or the supported sign-in flow, and inspect which project or personal configuration the chosen action affects.

prepare-connection.cjs prints a complete inactive TOML fragment from this Node executable and extracted server path; no placeholder executable is needed. In the app choose Settings → MCP servers → Add server, select STDIO, enter those values, save and Restart. CLI offers codex mcp add NAME -- COMMAND and codex mcp list; IDE uses its gear menu and Restart extension. A trusted project can instead use the reviewed fragment in .codex/config.toml while preserving existing contents. Perform the native T-102/T-999 lookup and reconcile it with the dataset. The launch diagnostic actually executes the three failure boundaries; it does not register a server or invent an OAuth response.

## Worked reference

### Read the handshake

The supplied harness requests a supported MCP version.

```text
initialize(protocolVersion=2025-11-25)
notifications/initialized
tools/list
tools/call(list_tasks)
```

```text
protocolVersion: 2025-11-25
capabilities: tools and resources
serverInfo.name: codex-howto-local-workbench
```

The server implements a deliberately documented protocol subset; no HTTP endpoint, authentication, or general interoperability certification is claimed.

## Common mistakes

- Equating registration in a list with successful authentication and data retrieval.

- Pasting a secret directly into a shared command, skill or configuration example.


## Troubleshooting

A path works from one folder but not another.

The proposed launch depends on the shell's current directory.

Use reviewed absolute executable/script paths or explicit documented cwd settings.

A running process is called a working connection.

No capability negotiation or tool response was observed.

Require initialize success and an actual known-record read before that claim.
