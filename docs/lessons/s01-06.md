## Your outcome

Combine natural-language requests, built-in controls and reusable skills without blurring their responsibilities.

## Environment

App / CLI / IDE

## Understand the concept

Use ordinary language to define the result, a built-in control to operate the client, and a skill to apply a repeated workflow. These are complementary tools. A request such as “explain this search and run its existing regression checks” defines work. /diff reveals changes. A project skill can provide a familiar review checklist. Stacking commands and skills without a clear outcome only makes the session harder to understand.

A good task names the relevant input, the allowed scope and an observable finish. In the Orbit Notes practice copy, inspect README.md, AGENTS.md and checks.cjs before asking for a search fix. The exercise brief supplies the real check command because the starter README deliberately contains an unsupported npm test instruction. Reproduce the uppercase and padded-query failures, preserve the supplied checks and unrelated files, and require evidence that the same cases pass after the change. Let Codex choose routine implementation details within that contract.

Keep facts and permissions separate. A README may explain how deployment works, but reading it does not authorize deployment. A review tool may return suggestions, but suggestions do not prove the code was changed. A completed test supports a particular behavior under its tested conditions. Finish with the actual changed files, checks performed, remaining gaps and a preview when the result is visual.


## Explore the details

### Read a real before-and-after result

The unchanged six checks expose two baseline failures: uppercase REVIEW and the padded query. The reference fix computes a trimmed lowercase needle and compares lowercase titles, while filter returns the original objects in their original order. The padded command must print n1: Review launch checklist and n3: Review documentation.

A map-based solution can match the same IDs but copy and lowercase the returned objects. The comparison exercise rejects that candidate through the identity contract. Inspect the implementation and protected files as well as the check summary; correct search IDs alone do not establish preservation.


### Recover from an unhelpful answer

First identify the missing input or broken assumption. If the wrong directory was inspected, fix the context. If the expected behavior was unclear, supply an example. If the change is correct but the proof is missing, ask for the relevant check. Starting a new chat can reduce clutter, but it does not repair the working tree or replace an evidence-based diagnosis.

## Common mistakes

- Adding repeated instructions to “be perfect” while leaving the expected behavior undefined.

- Approving a result solely because the agent reports success or because a generic lint command passed.


## Troubleshooting

All checks pass after expected IDs were removed.

The tests were weakened instead of the implementation repaired.

Restore the supplied contract and fix the normalization behavior.

The model reports success but the file did not change.

The response described a proposed edit rather than a saved artifact.

Open notes.cjs and inspect the actual diff before accepting completion.
