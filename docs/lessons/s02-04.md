## Your outcome

Organize project-specific instructions without confusing documentation rules with sandbox command policy.

## Environment

App / CLI / IDE

## Understand the concept

The word rule can refer to two different things. A prose rule might say how to write a changelog; an execution rule controls whether a command can run outside the sandbox. The Claude source uses modular Markdown rules, including path-specific metadata. Codex does not inherit that .claude/rules format simply because the repository contains it. Use documented Codex instruction discovery and explicit references instead.

For modular guidance, keep AGENTS.md short and point to a focused document when a task needs it. A UI guideline file can explain naming, accessibility and visual checks without loading a long design policy into every unrelated task. Nested AGENTS.md files can specialize guidance by working directory. A reference is a reading instruction, not a guarantee that arbitrary linked Markdown has already been loaded automatically.

Codex execution rules are a separate, currently experimental feature using .rules files and prefix_rule entries. They match command argument prefixes and return allow, prompt or forbidden decisions. When several rules match, the most restrictive decision wins. Project-local rule layers require project trust. Do not put stylistic preferences in that file type or treat an allow decision as user authorization to send, publish or alter an external system.


## Explore the details

### A concrete policy result without installing a rule

The supplied review.rules prompts for the prefix node --test and forbids the narrower node --test private-checks.cjs. The two evaluator examples show why the stricter matching decision wins. The file lives outside active .codex/rules locations; evaluating it does not grant permission or run checks.cjs.

For the writing exercise, keep the convention in Markdown and reference docs/writing-guidelines.md from AGENTS.md. Correct the unsupported README command, label it unrun until executed, and compare the resulting document. Prose instructions and execution-policy syntax solve different problems.


### An execution rule is not a style rule

If you later need command policy, study the official prefix matching and test tools before installing a rule. A harmless-looking command wrapper can contain more than one action, so broad exceptions require care. This beginner exercise deliberately changes only project documentation. It teaches the distinction without weakening the learner’s sandbox or modifying personal command approvals.



## Example

```markdown

Use that file for heading and example conventions.
For code-only tasks, read it only when the task also changes public documentation.
Preserve unrelated edits and report the actual validation performed.
```

## Common mistakes

- Copying .claude/rules files unchanged and assuming Codex interprets their metadata.

- Allowlisting a broad shell prefix to make a writing convention easier to follow.


## Troubleshooting

The linked guide is never consulted.

The reading condition or relative path is unclear.

Name the actual reference path and verify the relevant task reads it.

A style requirement leads to a broad command allowlist.

Documentation guidance and execution policy were conflated.

Keep the style rule in prose; do not weaken the sandbox to satisfy it.
