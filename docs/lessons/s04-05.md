## Understand the concept

Background delegation means a child can work while the parent handles an independent activity. It does not establish completion, persistence through every interruption, recurring execution or resource cleanup. For this capstone, a worker can implement one bounded module while the parent prepares the integration checklist from CONTRACT.md. The parent must still wait for the required implementation output before accepting the combined candidate.

Current Codex clients expose subagent activity, and the CLI provides /subagents for inspecting and switching threads. App and IDE controls can differ. Use the actual client's controls and record only observed states. Do not import Claude background front matter, Ctrl+B behavior or environment flags. A child that needs a fresh approval in a non-interactive situation may fail rather than opening a dialog; report that concrete gap instead of inventing its result.

The local simulate.cjs program is deliberately different: it deterministically prints work-package handoffs and runs the supplied reference integration. Its actualAgentsSpawned field is false. Use it to understand ownership and dependencies, then label any optional real Codex run separately. If a worker finishes before you observe a running state, report dispatch and return only. Recheck the resulting code version, because an earlier completion message does not prove later files still meet the contract.

In the app, open the child thread shown in main-chat activity, inspect its latest file/result, then ask the main chat to steer or stop that named child if needed. CLI switches threads with /subagents; the IDE panel depends on the client. Try a concrete error: a worker starts editing report.cjs despite owning normalization. Stop the overlap, preserve useful work, assign report.cjs one owner and rerun combined checks on the final files. Stopping a conversation does not rewind file edits. This dispatch→inspection→steering→checked return uses actual Codex controls rather than Claude-specific background shortcuts.

## Common mistakes

- Calling a background task durable automation or promising completion after the computer becomes unavailable.

- Importing a Claude background shortcut and interpreting an unobserved action as successful.


## Troubleshooting

Simulation output is presented as evidence of two running agents.

Deterministic package records were mistaken for actual client activity.

Label the script honestly and supply separate thread/activity evidence for any real run.

Stopping a child is assumed to remove every process or artifact.

Agent state and resource cleanup were conflated.

Inspect the relevant actual process/files separately and preserve needed work before cleanup.
