## Understand the concept

The source lesson opens a dedicated checkpoint browser. In Codex, begin with the evidence your client actually offers: saved chats, the review panel and the repository’s version history. The desktop app documents a review-tab shortcut, including Ctrl+Shift+G on Windows. The CLI /diff command displays working changes. Neither interface should be described as a browser of guaranteed automatic file snapshots.

A useful recovery inspection answers what changed, which files belong to the experiment, and which baseline you intend to restore. Git status distinguishes tracked edits and untracked files; a normal git diff does not display an untracked file’s content. Codex /diff is documented to include untracked files, but you should still inspect their paths and contents. Do not let a clean-looking partial diff hide a newly generated file.

A chat transcript adds intent and tool history, while repository history adds file versions. Compare both when a change appears unexpected. A commit timestamp alone does not prove that all relevant files were included. The linked Orbit Notes --git copy deliberately uses a staged index baseline and has no HEAD commit: inspect it with git show :README.md. In a different repository with a verified commit, git show HEAD:README.md and git log inspect that committed history instead. Record the actual baseline type rather than assuming those commands are interchangeable.


## Explore the details

### Read the index, worktree and untracked output separately

In this no-commit teaching repository, AM README.md means the file is added in the index and modified in the worktree. The untracked notes-draft.md appears as ??. git diff -- README.md compares the working candidate with the index; it does not include the draft’s contents. Open that file separately.

git show :README.md reads the staged version. git show HEAD:README.md cannot read a commit that does not exist here. The linked exercise records these real states and makes the baseline type explicit, so missing HEAD is understood rather than addressed through identity or remote changes.


### When Git is unavailable

Use a separate known-good copy and compare the named file directly in an editor. Record that the exercise used a copy rather than pretending a commit exists. Do not install Git or alter global settings just to complete this inspection. The same reasoning applies: establish the source of the baseline, include newly created files in the inventory and preserve any work outside the experiment.

## Worked reference

### Inspect a real narrow diff

The optional Git verifier creates a new index-only repository and saves its actual evidence.diff. It does not create a commit or alter Git identity.

```shell
git status --short
git diff -- README.md notes.cjs
git show :README.md
```

```text
README.md and notes.cjs have working edits against the staged baseline.
WORK-NOTE.md, notes.json and checks.cjs have no working diff.
HEAD has no commit in this teaching repository.
```

The Git index supplies the comparison point. An AM status is expected here; it is not a mysterious merge state. Untracked outputs still require separate inspection.

</details>

## Common mistakes

- Restoring files from the newest commit without checking whether that commit is the desired baseline.

- Equating a conversation timestamp with proof that the corresponding file version is available.


## Troubleshooting

git show HEAD fails in the provided Git exercise.

The lab deliberately uses an index baseline without an identity-dependent commit.

Use git show :README.md and document the baseline type.

A new draft is absent from the diff.

It is untracked.

Inspect status and the actual file separately; do not assume it is protected.

## Knowledge check

Why can git status show a file that ordinary git diff does not display?

1. The file may be untracked.
2. Git status always invents extra files.
3. The file is guaranteed to have no useful content.

<details><summary>Reference answer — attempt first</summary>

1. The file may be untracked.

Untracked files are reported by status but are not included in a normal working-tree diff until separately handled.
